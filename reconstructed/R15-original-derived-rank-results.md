# 2. What they found

## Original-static authority and finite grade

**CONFIRMED STATIC:** E042 M2b47 / T0241 supplies XH0/SH1/X2/S3/A4/B5/C6/D7/F8/N9.
Grade reads UInt16 n300 then virtual whole total, stores Single quotient; separately
reads UInt16 n50 and another total; only then reads success. Whole total sums
n50+n100+n300+MISS in Int32 and omits decorated counters. Hidden8 or Flashlight1024
are separately fetched/short-circuited for silver X/S. No score, accuracy getter,
max/current combo, perfect or validity participates in grade. Getter is uncached.

**RECONSTRUCTED:** .NET8 stored binary32 quotient then explicit Double comparisons
preserve the finite E042 profile. In particular80/20→A,70/30→C,60/40→C; a successful
empty artificial record has NaN proportions→D while accuracy getter returns1f.
A failed record still performs both proportion operations before F. These are
conditional component controls, not claims that an empty chart is playable.
Unresolved original-x86 extended-intermediate precision remains visible.

## Record identity, preparation and admission

`SessionRankRecord` retains the exact CircleSession and its ScoreLedger. Score,
accuracy, UInt16 whole counters and max combo read that ledger directly. Its stable
SessionIdentity is distinct from map identity. HandlerRecord initially aliases
GlobalRecord; SelectedRecord binds the then-current global reference only at
Initialize, after Commit's cleanup. No completed-ledger copy replaces those
relationships. Artificial global replacement/mismatch and cleanup mutation controls
exercise this actual production model. No authoritative grade cache is introduced.

`Success` is written from NOT the known health failure latch at completion; it is
never inferred from accuracy or positive last judgement. Unknown health/failure
provenance blocks the normal completion route. The E027 failed outer-caller guard
also blocks normal automatic Rank; a failed-grade getter alone does not imply that
Rank was reached. A later controlled global record F still routes the selector to
SelectPlay5 after invalidation. Live practice failure continuation is retained and
ends with a clearly labelled unavailable panel, not a fabricated original F screen.

`Valid` is independent. Count mismatch invalidates but still completes; invalidation
does not rewrite score or grade. The normal host adds an **ENGINEERING safety**
condition deferring while kernel whole judgements remain pending. It never drains
pending slider/spinner components or invents accounting to satisfy results.

Perfect uses E035's completed calibration/chart and R10 fresh grouping provenance.
For each slider a=subset+2, b=schedule−subset−1, accumulate unchecked a+b−1, then
add1 for each completed object. Compare `!(unchecked(prepared-maxCombo)>0)` as E042
M0acd. This is a read-only reconstruction of F05fd's accepted full-trial scalar;
no HP calibration arithmetic is changed or new live component emitted. Missing
preparation leaves Perfect=null and the UI explains its unsupported eligibility.
Perfect may be false at100% or true below100%; no universal no-MISS shortcut.

`RankPolicyInputs` explicitly requires ordinary0/no-mod/fresh/no recorded source,
no restore/reuse/alternate record or accumulator. Exact fresh map/score metadata
and supported ledger are additionally checked. Source-row count>=7000 rejects
base legacy Rank, preserving E023's automatic ScoreV2 boundary. Existing gameplay
scoring remains untouched; this does not claim those larger charts have faithful
base legacy original policy. Fresh live/no-source/no-mod excludes M2234's alternate
